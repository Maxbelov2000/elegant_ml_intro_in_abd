**Интерпретация:** модель объясняет 78.5% дисперсии цен на тест. R² на test выше чем на train — признак хорошей обобщающей способности, а не переобучения. Каждый третий автомобиль оценивается с ошибкой не более 10%.

### Важность признаков (по коэффициентам Ridge)
1. `max_power` — главный фактор, мощность напрямую определяет ценовой сегмент
2. `year` — год выпуска, новее = дороже
3. `brand_*` — марка автомобиля, огромный разброс между бюджетными и премиум
4. `transmission_Manual` — механика значительно дешевле автомата
5. `km_driven` — пробег, отрицательная связь

## 3. Что дало наибольший прирост качества

**Добавление категориальных признаков** — самое важное улучшение:
- Только числовые признаки: R² ≈ 0.60
- С категориальными (OHE): R² ≈ 0.785

Прирост +0.185 по R² и −128k по RMSE. Категориальные признаки (`brand`, `transmission`, `fuel`) несут информацию о рыночном позиционировании автомобиля, которую числовые характеристики двигателя не передают.

---

## 4. Что сделать не удалось и почему

**Нелинейные модели (Random Forest, Gradient Boosting)** — не входили в задание данной части. По всем признакам (нелинейные зависимости по PhiK, скошенные распределения, выбросы) ансамблевые методы должны дать R² > 0.90. Это следующий шаг.

**Log-трансформация таргета** — визуализация показала, что log(selling_price) близко к нормальному распределению. Обучение на log-таргете с обратным преобразованием предсказаний должно улучшить метрики, особенно business_metric. Не реализовано в рамках задания.

**Обработка выбросов** — автомобиль с пробегом 2.36 млн км и несколько авто дороже 5 млн сильно влияют на обучение линейных моделей. Удаление или winsorization выбросов не выполнялось.

**Кросс-валидация на финальных метриках** — GridSearchCV подбирал `alpha` по CV, но финальные метрики (R², RMSE) считались на фиксированном test. Более корректная оценка — через k-fold на всём датасете.

## 5. Оценка разработанного сервиса

### Что получилось хорошо
- **EDA-вкладка** — наглядно: распределения, корреляции, boxplot по категориям. Хорошо передаёт структуру данных
- **Сравнительная таблица моделей** — все метрики в одном месте с цветовой градиацией
- **Ручной ввод предсказания** — интуитивный интерфейс с слайдерами и селекторами
- **Похожие авто** — полезная функция для контекста предсказания
- **Веса модели** — интерактивный слайдер числа признаков, группировка по типу

### Что получилось менее удачно
- **Business metric 32%** — каждые 2 из 3 авто оцениваются с ошибкой > 10%. Для реального сервиса неприемлемо, нужны нелинейные модели
- **Отрицательные предсказания** — линейная регрессия не ограничена снизу, для очень старых/дешёвых авто может выдать отрицательную цену (обрезаем в 0, но это костыль)
- **Scatter plot** — основная масса точек сжата в угол из-за выбросов, трудно оценить качество в дешёвом сегменте
- **Время загрузки** — обучение 4 моделей + GridSearchCV при каждом запуске занимает ~2-3 минуты. Решение — загрузка из pickle

### Ограничения сервиса
- Данные индийского рынка (рупии, марки Maruti/Tata), не применим к российскому рынку без переобучения
- Модель не знает о новых марках, не встречавшихся в train (заполняются нулями в OHE)
- Нет валидации введённых данных (можно ввести пробег 999 999 и получить предсказание)

### Планируемые улучшения
1. Обучить **CatBoost/LightGBM** — нативная работа с категориальными признаками, должны дать R² > 0.90
2. Применить **log-трансформацию** таргета — улучшит business_metric
3. Добавить **доверительный интервал** предсказания через bootstrap
4. Ускорить запуск — **загружать модель из pickle** вместо обучения при каждом старте
5. Добавить **валидацию входных данных** и понятные сообщения об ошибках
